## 0. TL;DR — если модель читает только один абзац

АМСУР — бесплатная программа для завуча белорусской школы, которая составляет расписание
автоматически: загружаешь нагрузку из Excel, нажимаешь «Сгенерировать» — получаешь пять разных
готовых вариантов расписания на неделю с оценкой словами и объяснением, почему один лучше
другого. Выбранный вариант можно подправить руками (программа объяснит, почему ход запрещён)
и выгрузить в Excel или распечатать. Работает офлайн на обычном школьном компьютере, ставится
одним файлом без прав администратора. На типовой школе (40 классов, 1196 уроков) считает
десятки секунд и выдаёт расписание с нулём «окон» у учеников и нулём поздних стартов.

---

## 1. Что это такое

**Одна строка:** АМСУР — автоматическое составление школьного расписания для типовой
белорусской школы.

**Абзац:** это настольное приложение (Windows), которое превращает таблицу нагрузки
(класс → предмет → часы в неделю → учитель → кабинет) в готовое недельное расписание.
Завуч не составляет расписание руками и не крутит настройки: он загружает Excel, жмёт
«Сгенерировать» и выбирает из пяти вариантов. Программа сама соблюдает жёсткие правила
(один учитель, класс и кабинет не могут быть в двух местах; смены; деление на подгруппы)
и оптимизирует мягкие (окна, поздние старты, плотность дня). Результат выгружается в Excel,
готовый к печати.

**Ключевая формула продукта (из документов проекта):** «максимально гибко, максимально просто».
Обычный завуч ничего не настраивает — работает профиль «Стандарт». Эксперт настраивает глубоко,
через интерфейс, без кода.

**Название:** АМСУР — в документации расшифровывается как «автоматический модуль составления
учебных расписаний». Полная официальная расшифровка аббревиатуры — **[уточнить]**.

---

## 2. Проблему какую решает

- Составление расписания на 40 классов вручную — это дни работы завуча: часы, смены,
  кабинеты, подгруппы, несовместимости учителей, пожелания. Каждый сдвиг одного урока тянет
  за собой остальные.
- Готовая таблица почти всегда содержит «окна» у детей (пустой урок в середине дня) — а это
  прямо то, чего не должно быть.
- Специализированные программы для расписаний существуют, но они либо платные, либо требуют
  настройки и обучения, либо живут в облаке и требуют интернета.

АМСУР закрывает это так: **бесплатно, офлайн, без установки, без обучения — один файл
и кнопка «Сгенерировать»**.

## 3. Кто пользователь

1. **Завуч (основной).** Не программист, не любит настройки, хочет результат. Работает
   с Excel. Именно под него сделан путь из пяти шагов.
2. **Эксперт внутри школы** (завуч-энтузиаст, директор). Ему — глубокие настройки: профили,
   слайдеры важности, предметы/классы/учителя/кабинеты, экспертный режим с числами.
3. **Комиссия/жюри, научный руководитель.** Для них важны: как работает внутри, честность
   заявлений, доказательства (тесты, замеры, реальные данные школы).

## 4. Что делает программа — путь завуча (это же — каркас любого ролика)

1. **Открыть программу.** Двойной клик по `AMSUR.exe`. Установка не нужна.
2. **Попробовать на демо** (1 клик): маленькая школа из 6 классов, чтобы увидеть результат
   сразу, без своего файла.
3. **Загрузить свою школу:** «Скачать шаблон» → заполнить в Excel (класс, предмет, часы
   в неделю, учитель, кабинет, смена) → «Загрузить Excel». Если в данных ошибка — программа
   напишет **что именно исправить** (например: «учителю некуда поставить уроки»).
4. **Нажать «Сгенерировать расписание»** (`F5`). Через секунды-минуты появляются **Top-5**
   вариантов: у каждого оценка словами (**Отличное / Хорошее / Требует внимания**) и кнопка
   **«Почему так?»** — объяснение человеческим языком, что именно портит оценку.
5. **Принять лучший → подправить руками (по желанию) → выгрузить в Excel** (или в HTML
   для печати в PDF). Выгрузка есть и с главного экрана.

Первый запуск с нуля — примерно час (в основном заполнение шаблона). Повторный, когда
нагрузка уже есть, — 10–20 минут. *(Формулировка «вместо дней ручной работы» — оценка
проекта, а не измеренный факт: в титрах лучше говорить «вместо дней — минуты» только если
это подкреплено вашим личным опытом.)*

## 6. Что внутри (для кадров «под капотом» и для доверия комиссии)

Стек: **.NET 10, WPF, SQLite (raw Microsoft.Data.Sqlite, без EF),
OR-Tools CP-SAT + собственный локальный поиск (Greedy + CompactRepair + VND + LNS)**.

Конвейер решения (в документации описан как 6 шагов «без математики»):

1. **Черновик за долю секунды.** Уроки расставляются жадно: берём урок — кладём в первую
   свободную клетку. Физкультура и языки — в первую очередь, им тесно.
2. **Уборка «окон».** Проход сдвигает уроки каждого класса в сплошной блок без дыр
   и поздних начал.
3. **Полировка.** Тысячи мелких ходов (переставить, обменять); каждый ход считается дешёвой
   формулой, худшее не принимается.
4. **Пять вариантов.** Поиск стартует с разных точек, похожие выбрасываются — остаются
   5 **разных**.
5. **Сторож.** Независимая проверка: хоть одно жёсткое нарушение — результат в мусор,
   файл не пишется. «Плохое расписание программа отдать не может физически».
6. **Повторяемость.** Тот же запуск = тот же результат (seed), любой замер можно перепроверить.

Архитектура (для слайда «как сделано»): `Domain` / `Scheduling.Core` /
`Scheduling.OrTools` / `Application` / `Infrastructure` / `Wpf` / `Tests`.

**Что зашито как жёсткое (нарушить нельзя никогда):** один учитель, класс и кабинет не могут
быть в двух местах одновременно; смены; синхронность подгрупп; 5-дневка; доступность учителя.

**Что оптимизируется как «пожелание»:** окна учителей (отдельно «внутри смены» — дорого,
и «между сменами» — дёшево, потому что это цена двухсменки), тяжёлые уроки на краю дня,
повторы предмета за день, кабинеты.

**Строгие правила для учеников (одинаковы для всех профилей):** 0 окон и старт не позже
2-го урока. Торговаться весами нельзя — только через «опасное» подтверждение.

## 7. Проверенные цифры (можно в титры)

**Масштаб и скорость**
- Типовая школа: **40 классов, 100 учителей, 40 кабинетов, 5 дней × 2 смены, 1196 уроков.**
- Смены (обновлено 16.10.2026): первая смена — 34 класса (1–5, 7, 8АБВ, 9АБВ, 10–11),
  вторая — **6А–6Г, 8Г, 9Г** (6 классов). 5-е классы переведены в первую смену, потому что
  по норме РБ (п. 92) им вторая смена запрещена.
- Жадный старт: **1196 из 1196 уроков за ~0,07 секунды на старт** (до оптимизации);
  4 старта с выбором лучшего — ~0,27 секунды.
- Вся генерация типовой школы: **десятки секунд** (замеры: 6–12 с на бюджет 10–20 с;
  pilot-прогон большой школы — 20–90 с).
- Режимы: **Быстро ~3 с / Стандарт ~12 с (по умолчанию) / Максимум ~30 с (5 стартов) /
  Топ-качество ~10 мин (к защите и пилоту)**.

**Качество результата**
- Эталонный результат на типовой школе: **0 окон у учеников, 0 поздних стартов**,
  40 классов. Перепроверено 16.10.2026 на новой раскладке смен: полный прогон —
  Feasible, 0 жёстких нарушений, валидатор чистый (CompactRepair не оставил ни одного
  неубранного дня).
- Разделение окон учителей: было 1389 «юнитов» окон, из них **994 (72%) — перерывы между
  сменами**, а не внутри смены. После честного разделения: окон внутри смены у учителей
  **310 → 200 (−35%)** при том же нуле окон у учеников и нуле жёстких нарушений.

**Реальные данные школы (пилот)**
- Реальное расписание школы №8 (5–11 классы) перенесено в программу **с 6 фотографий
  висящего расписания** → **24 класса, 396 строк, 769 часов в неделю**.
- Движок на этих данных: **878 из 884** уроков жадным стартом, «уборка окон» 21 → 10.

**Надёжность**
- Около **460 автоматических тестов**, полный прогон ~10–13 минут; последний полный прогон:
  **457 пройдено, 0 упавших, 11 пропущено (всего 468)**.
- Тесты покрывают валидатор правил, солвер, подгруппы, персистентность, профили качества,
  экспорт (Excel/HTML/CSV), запуск всех окон интерфейса, E2E-цикл «данные → расписание → файл».

**Форма поставки**
- **Один самодостаточный файл `AMSUR.exe` (~218 МБ)**, рантайм внутри: **устанавливать
  ничего не нужно**, права администратора не нужны, интернет не нужен.
- Windows 10/11, 64-bit.
- **Бесплатно, лицензия MIT, открытый исходный код.**

**Демо**
- Демо-данные: маленькая школа **6 классов, 56 строк** — загружается одной кнопкой.

## 8. Фишки, которые хорошо смотрятся в видео

1. **Демо в один клик** — «смотрите результат прямо сейчас, без моего файла».
2. **Top-5 разных вариантов**, а не один — с оценкой словами и кнопкой «Почему так?».
3. **Объяснение вместо чисел:** «Отличное / Хорошее / Требует внимания» + топ-3 «что можно
   улучшить» + окно «Почему так», где назван виновник (класс/учитель, день, уроки).
4. **«Стоп» без потери лучшего** — можно прервать поиск и всё равно получить лучшее найденное.
5. **Ручная правка с объяснением:** «можно / можно с ухудшением / запрещено + причина».
   Это защита, а не ошибка.
6. **Сторож:** при жёстком нарушении файл не пишется вообще.
7. **Черновик вместо пустоты (новая фича, 16.10.2026):** если за отведённое время полное
   расписание не нашлось, программа показывает **лучшее найденное + добивает остаток
   послаблениями, которые разрешила школа**, и честно перечисляет нарушения словами —
   и в окне, и в Excel-файле. Замер на тяжёлой школе (994 урока): **991 из 994** вместо
   пустого экрана, файл выгружается.
8. **Гибкость без кода:** ~20 слайдеров «Не важно … Очень важно», четыре профиля качества
   (Стандарт / Удобно ученикам / Удобно учителям / свой «Моя школа»), редакторы
   предметов/классов/учителей/кабинетов.
9. **Данные школы сохраняются** между запусками (SQLite), кнопка «Сохранить „Моя школа“»
   с восстановлением при старте.
10. **Персональное расписание учителя** отдельной выгрузкой — «кому когда какой класс».

## 9. Чем отличается от «вручную в Excel»

| | Руками в Excel | АМСУР |
|---|---|---|
| Время на 40 классов | дни | десятки секунд |
| Окна у учеников | появляются, ищутся глазами | жёсткое правило: 0 окон, старт не позже 2-го урока |
| Конфликт «учитель в двух местах» | ловится глазами | валидатор не пропустит |
| Варианты | один | 5 разных + объяснение, почему этот лучше |
| Правка | ломает что-то молча | объясняет, почему ход запрещён |
| Проверка перед выдачей | нет | независимый сторож: нарушение → файл не пишется |
| Переносимость | файл Excel | один exe на флешке, офлайн |

Про «зарубежные/платные аналоги» в ролике лучше **не сравнивать по названиям** — публичных
замеров «АМСУР против них» у проекта нет. Корректная формулировка: «есть платные и облачные
решения; наше — бесплатное, офлайн и настраивается без обучения».

## 10. ЧЕГО НЕЛЬЗЯ ГОВОРИТЬ (соблюдать строго)

Это не придирки: проект принципиально строится на честных ограничениях, и завышенное
обещание в промо обесценит всё остальное.

1. **Никогда «оптимальное расписание».** Только **«лучшее найденное»** — поиск ограничен
   временем. Формулировка «идеальное» тоже неуместна.
2. **Не утверждать соответствие СанПиН как юридический факт.** Нормативы в программе —
   рабочая выборка, помечены **NEEDS-CHECK** (требуют сверки с НПА). Можно говорить:
   «учитывает нормы нагрузки (недельные часы, максимум уроков в день)», нельзя:
   «расписание гарантированно соответствует СанПиН». Три конкретных примера (сверка
   16.10.2026): (а) дневной максимум уроков — **правило школы**, в СанПиН РБ такой нормы
   нет, не называть её «по СанПиН»; (б) недельные часы 5/7/8 классов в прототипе выше
   белорусского потолка — открытый вопрос к завучу; (в) в типовой школе **9Г учится
   во второй смене**, а п. 92 IX классам вторую смену запрещает — это решение школы
   по ёмкости, в ролике не подавать как «всё по нормам».
3. **Таймаут — это не «невозможно».** Правильные статусы: «не найдено за отведённое время»,
   «остановлено, лучшее сохранено».
4. **Не обещать замены «на завтра» при больничном** — этой функции пока нет (запланирована).
5. **Не заявлять работу на macOS/Linux** — приложение на WPF, только Windows.
6. **Не показывать персональные данные детей.** Их в программе нет вообще: только классы,
   предметы, часы, учителя, кабинеты. Фамилии учителей в пилотных данных — плейсхолдеры.
7. **Не выдавать оценки времени («вместо недель») за измеренный факт.** Измерено: секунды
   и минуты машинного времени. Сколько дней занимает ручная работа — это оценка, и в ролике
   её надо либо не называть, либо подавать как личный опыт автора.
8. **Не приписывать проекту ИИ-магию.** Внутри — математическая оптимизация (CP-SAT
   и локальный поиск), а не нейросеть. Это, кстати, сильнее звучит: детерминированно,
   повторяемо, без облака.
9. **Не называть непроверенные цифры.** Всё, чего нет в разделе 7, в титры не идёт.

## 11. Тон, стиль, аудитории

- **Тон:** спокойная уверенность без пафоса. Проект сам себя ограничивает в обещаниях —
  это его фишка, её и продавать: «мы не обещаем невозможного, мы показываем, что нашли,
  и объясняем».
- **Голос:** говорит тот, кто это сделал и кому не всё равно, что завучу удобно.
- **Аудитории ролика:**
  - завуч → «тебе не придётся это делать руками»;
  - учитель → «у тебя не будет окон и разорванных дней»;
  - комиссия/жюри → «вот как это работает внутри, вот тесты, вот реальная школа, вот
    честные ограничения».
- **Визуальный язык:** чистый десктопный интерфейс, крупные кнопки, живые таблицы Excel
  рядом с приложением. Никаких абстрактных «нейросетевых» визуализаций — продукт конкретный
  и инженерный.
- **Ключевой приём:** контраст «до/после». До — Excel с расписанием, где красным подсвечены
  окна у детей. После — АМСУР: ноль окон, пять вариантов, объяснение.

8. **115–120 с.** Финал: «АМСУР. Расписание, которое считается само».

## 14. Технический факт-лист (копировать как есть, без округлений)

- Название: **АМСУР** (автоматический модуль составления учебных расписаний).
- Назначение: автоматическое составление школьного расписания для типовой белорусской школы.
- Платформа: **Windows 10/11, 64-bit** (WPF). Поставка: **один самодостаточный exe ~218 МБ**,
  рантайм внутри, установка не требуется, интернет не требуется, права администратора
  не требуются.
- Стек: **.NET 10, WPF, SQLite (raw Microsoft.Data.Sqlite, без EF), OR-Tools CP-SAT
  + собственный локальный поиск (Greedy + CompactRepair + VND + LNS)**.
- Лицензия: **MIT**, бесплатно, открытый код.
- Типовая школа в тестах: 40 классов (1–9 АБВГ, 10–11 АБ), 100 учителей, 40 кабинетов,
  5 дней × 2 смены, **1196 уроков**; эталонный результат — **0 окон у учеников,
  0 поздних стартов**.
- Режимы генерации: Быстро ~3 с, Стандарт ~12 с, Максимум ~30 с (5 стартов),
  Топ-качество ~10 мин.
- Профили качества: Стандарт (по умолчанию), Удобно ученикам, Удобно учителям,
  свой «Моя школа» (сохраняется в SQLite).
- Демо-данные: школа из 6 классов, 56 строк, загружается одной кнопкой.
- Пилот: школа №8, 5–11 классы — 24 класса, 396 строк, 769 часов в неделю,
  данные собраны с 6 фотографий расписания.
- Нормы нагрузки РБ, использованные как ориентир (рабочая выборка, NEEDS-CHECK):
  недельные часы 21 / 23 / 29 / 30 / 32 / 33 / 34 (1 / 2–4 / 5 / 6 / 7 / 8–9 / 10–11);
  максимум уроков в день: 1 класс — 4 (раз в неделю 5 при трёх физкультурах),
  2–4 классы — 5, 5–6 классы — 6, 7–11 классы — 7.
- Тесты: ~460 автоматических, полный прогон ~10–13 минут; последний полный прогон —
  457 пройдено, 0 упавших, 11 пропущено, всего 468 (пропуски — известные
  тяжёлые/карантинные сценарии, не сломанные тесты).
- Объяснения в интерфейсе — человеческим языком: «Отличное / Хорошее / Требует внимания»,
  топ-3 «что можно улучшить», отдельное окно «Почему так».
