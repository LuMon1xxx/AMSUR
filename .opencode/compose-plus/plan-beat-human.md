## Фаза 1 — DayCloseLns (ядро, новое; прогноз −45..−60; гейт: хвосты ≤70, итог ≤200)
1. Новый `src/Amsur.Scheduling.Core/DayCloseLns.cs` — зеркало структуры
   `TeacherDayLns` (WorstTeacherDays переиспользовать; ruin/topK/restarts/
   лексикография/детерминизм — те же):
   - `RuinTeacherDayClose`: ВСЕ уроки (учитель, день) + sync-замыкание
     (как в TeacherDayLns), БЕЗ class-contention расширения (день должен
     опустеть; contention пусть чинит фаза TeacherDayLns до/после).
   - Replant с `GreedyPlacer.DayReuseHint(teacher)`: ordering дней — сначала
     ОТКРЫТЫЕ дни учителя (где teacherDay > 0), потом остальные; внутри дня
     обычный порядок. Новый opt-in record рядом с CompactHint; default null =
     бит-в-бит старое поведение. Cap-aware: UnitFits уже режет перегрузы.
   - Принять строго лексикографически (gaps, failedDays, soft) — как TeacherDayLns.
2. `GreedyPlacer.TryPlaceUnit`: ветка `reuse` в orderedDays (по образцу `pack`):
   `days.OrderBy(d => teacherDay.GetValueOrDefault((first.TeacherId, d)) == 0 ? 1 : 0).ThenBy(класс-заполнение как было).ThenBy(d)`.
3. Тесты `DayCloseLnsTests` (образец TeacherDayLnsTests + ActiveDayTests):
   never-worsens, детерминизм (2 прогона = бит-в-бит), day-close кейс
   (тощий день закрывается), паритет не нужен (движения — обычные time-moves
   через существующий SearchIndex).
4. Стадия в `ScratchGen.RunFullPipeline` после teacher-lns блока (rules threadyтся).
   Хвосты брать из `TeacherDayLns.WorstTeacherDays` (topK 24–32, restarts 4–6,
   бюджет 60–120с × 3 сида, отбор min-gaps).
5. Риск: пятничные хвосты (поглощать некуда — кэпы классов 7/8). Митигация:
   day-close сначала на Пн–Чт хвостах; Пт — отдельной строкой замера.
