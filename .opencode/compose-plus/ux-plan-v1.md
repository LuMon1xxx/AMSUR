## 0. Зафиксированные ответы пользователя

1. Всё в одном окне. Профи — за кнопкой «⋯ Больше функций» рядом, без двух режимов.
2. Ручной ввод НАРАВНЕ с Excel, удобнее Excel (кнопки, подсказки, примеры).
3. Ручная правка ПОКА НЕ НУЖНА, но спроектировать место + концепцию сейчас.

## 1. Функции — инвентаризация (ГЛАВНАЯ / вторичная / ПРОФИ)

Легенда: ГЛАВНАЯ — путь завуча, крупная кнопка всегда видна. Вторичная — обычная кнопка на экране. ПРОФИ — только за «⋯ Больше функций». СКРЫТА — место зарезервировано, в UI не видна.

## 2. Навигация rail (7 пунктов)

1. Главная 2. Школа и данные 3. Настройки качества (внутри Профили) 4. Генерация расписания 5. Расписание 6. Экспорт и печать 7. Справка (F1). «Профили» — редирект в Настройки. «⋯ Больше функций» — не маршрут: локальные Expander-проекции достаточны; глобальный персист-флаг отложен в P-next (не плодить второй источник истины без нужды).

## 3. Ручной ввод удобнее Excel (приёмы)

Конструктор строкой с примером, комбо с явным «+ Создать» (с превью, не тихо), умолчания (кабинет любой, часы из норм, MaxPerDay 6/2, 25 учеников, 5×7), мастер «Моя школа за 5 шагов» (Сетка→Классы→Учителя→Нагрузка→Проверка, «3 из 5», Дальше переключает таб), табы со счётчиками, тёплые пустые состояния, один DraftBuffer → dry-run → AcceptRows.

## 4. Правка-будущее (решения пользователя 24.09.2026, без кода)

- Swap: Move + Swap с подтверждением (свободная — Сохранить ход; занятая — Поменять местами с предпросмотром обоих).
- Undo: ПОЛНЫЙ стек отмен/повторов сразу (ChangeSet журнал, версии append-only, откат новой версией).
- Что править: ТОЛЬКО принятое (активное) расписание; Top-5 — только просмотр. Кабинет — вторым шагом отдельно, ONLY подсвечивать. Классный час — только целиком.
- Проверка при правке: ПОКАЗЫВАТЬ ВСЁ на экране — окна учителей, окна учеников, нормы СанПиН и т.п. (живая панель качества хода: вердикт + дельта + affected + полный разбор, не только «можно/нельзя»).
- Выбор кликом → «Переместить в…» кликом по пустой / «Поменять местами» по занятой → Проверить ход (вердикт словами + вся инфа) → Сохранить. Очередь P3: 1) affected N + disruption-строка в Preview 2) swap 3) undo/ChangeSet полный стек 4) DnD 5) пакетные 6) черновик-буфер.

## 5. DECISION CHECKLIST

1. Отклонено: удаление кодов QUICK/EXPERT (ломает сьют, оставлены алиасами); отдельный view Профили (второй источник QualityRules); 4 параллельных редактора без DraftBuffer (рассинхрон); disabled-заглушки правки (мёртвый код); мёртвая PDF-кнопка до D5; удаление HTML до PDF (дыра без Office).
2. Противоречия разрешены: режимы 4 кода/3 в UI; профили селектор на Главной + редактор в Настройках; Больше функций = локальные Expander-проекции (глобальный персист-флаг отложен в P-next); ввод = whole-buffer dry-run; правка = E8 жив + скрыта Visible=false; экспорт = HTML до PDF + два gate.
3. OWN SYNTHESIS: «3 в UI / 4 в API», «селектор на Главной + якорь в Настройках», «DraftBuffer», «PdfFinal/PdfDraft два контракта».
4. Остаточные риски: R1 путь завуча, R2 враньё UI, R3 сьют, R4 флаг-истина, R5 ложные красные, R6 PDF-лицензия D5, R7 E8-регресс, R8 бюджеты/бенчи, R9 draft-как-финал — см. risks (критика §Риски).
5. UI↔архитектура: rail+ViewHost сохранить; Профили-якорь; Больше функций — локальные Expander (без глобального флага, см. п.2); ввод через AcceptRows; режимы только GenerateModes+Dashboard (+ тесты/E4-E6 в scope); PDF за ISchedulePdfExporter после D5; правка через ManualEditService.
6. Логика↔UX: каждый ввод маппится на RuleCode Hard/Soft/Disabled + подтверждение Dangerous; Student-Hard един для профилей; тексты ошибок из одного источника.
7. Не покрыто: движок PDF (после D5), тёмная тема vs печать (печать всегда светлая), CSV скрыт, название пункта Генерация, мастер сворачиваемость.
